# 自主会话协作 / Autonomous Session Collaboration

同 Host/profile 的独立 Session 自动协作插件。人只需把任务交给 Agent，无需加入通讯录、勾选工作区或手动发信。不修改 DSH Core。

## 使用逻辑

- 所有普通、未归档且已加载为 running/idle 的 Session 默认参与。`collab_discover` 返回真实会话名、工作区、状态以及内部路由 ID；按名称查询时，只有没有 live 同名会话匹配，才会检查已关闭的持久会话（状态 `closed`）。
- Agent 判断要联系谁，调用 `collab_send`；空闲对方自动唤醒，忙碌对方通过 `steer` 在下一个安全的模型步骤接收。**已关闭的会话会自动重新打开再投递**：显式给 ID 时直接唤醒；按名称时若只有唯一匹配的已关闭会话，也会先唤醒。重名仍会先询问，绝不会随便挑一个唤醒。
- 收到问题的 Agent 自己使用 `collab_reply` 返回结果或追问。
- Session 名称允许重名（同工作区也可以）。`collab_discover` 支持精确 `name`、`workspace` 筛选，返回重名标记。发信支持 `target_name` 和可选 `target_workspace`：唯一目标直接发送；用户已明确给出工作区或既有上下文能唯一定位时自动发送；否则由 Host 调用 DSH 的用户提问机制让你选择，未选择前不投递、不群发。单独填一个内部 ID 不能绕过重名检查。
- 确实已有唯一任务上下文时，Agent 可用精确 ID + `target_context` 引用该依据；这只是模型提供的上下文说明，不是用户授权凭据，不能杜撰来逃避询问。回复沿原消息线程，创建后的初始任务沿新建的精确 ID，不因重名反复提问。重试同一个 request_id 不重新解析名称或转投另一个会话。
- 需要新的协作者时调用 `collab_create_session`，提供工作区（可省略使用当前工作区）、描述性名称、初始任务，以及二选一的模型来源：任务难度 1–5，或用 `model` 直接指定可用区里的一个模型（按 `collab_models` 的名字、模型 id 或 `provider/model`）；可选 `reasoning_effort` 指定该模型支持的一档，省略时用最高档。可选 `agent_preset` 指定模式，省略时使用默认模式。可用模式由 `collab_models` 返回。
- 新协作者与 DSH 原生新会话使用同一用户默认权限；默认 Agent preset 不变，只有显式传 `agent_preset` 时才使用其他模式。不强制只读、不继承发送方临时提权，也不改变全局默认模型。
- 插件不是后台自动转发所有聊天内容。自主判断和回复由 Agent 工具与提示完成，只有主动发送的协作内容会进入另一会话；不共享完整私人历史。

## 唯一设置：模型排序

左侧“会话协作”默认打开模型排序：

1. 上方可用区从上到下表示简单任务到专家级任务使用的模型顺序。
2. 拖动可改变顺序；拖到下方停用区就不再使用，拖回上方重新启用。不使用复选框。
3. 拖动后自动保存；也提供上移/下移/停用/启用按钮以支持键盘操作。
4. Agent 评估 difficulty：1 简单、2 有限任务、3 常规实现、4 复杂跨模块、5 专家架构/不确定研究。模型索引为 `round((difficulty-1)*(可用模型数-1)/4)`。也可以不按难度，直接用 `model` 指定可用区里的模型；停用区模型和不在名单里的模型一律拒绝，显示名、模型 id 与 `provider/model` 都可用来匹配。
5. 默认采用被选模型支持的最高思考强度；创建时可显式传 `reasoning_effort` 指定该模型支持的一档（档位列表由 `collab_models` 的 `efforts` 返回），不支持的档位直接拒绝，不静默降级或取整。没有思考强度的模型不虚构参数，也不接受 `reasoning_effort`。停用模型绝不被自动选回。
6. 模型来源仅是当前 DSH 已注册提供方公开的模型目录。已不存在的提供方、成功刷新后已移除的模型会自动从排序中清除，不从历史设置复活。新增模型进入停用区；仍存在的模型保留相对顺序。提供方目录临时查询失败时不把缺失误判成永久移除。

全部模型停用时，新建协作者明确失败，不偷偷继承其他模型。Agent 可读 `collab_models`，可以按名字直接选用可用区模型并指定其支持的思考强度，但不能重排、启用模型或指定停用模型。

## 只读通信日志

第二个页签只展示发生过的通信和创建记录：来源会话名、目标会话名、内容、时间、真实投递/处理证据。不显示一串 Session ID 作为名称，也没有发送/回复/创建表单。历史改名后优先显示当前标题，无法读取时保留发送时名称。

## 状态与边界

- 同一 Host/profile；只发现当前 live 普通 Session，历史未加载或已归档会话不自动唤醒。Subagent 保持原生父子路由，且子代理 scope 在 `agent/created` 时用 `tools.restrict` 隐去这六个协作工具：既不占它们的提示词，也不会让它们看到只会被拒绝的定义（调用路径仍以 `NOT_INDEPENDENT` 兜底）。已持久化但已关闭的 subagent Session 也不会进入 closed 候选，显式 ID 会在 resume 前以 `NOT_INDEPENDENT` 拒绝，不会先唤醒再失败。
- Peer 消息保留 DSH `agent-message/relay` 来源，并在模型输入中标注会话名。不能作为人类批准、系统指令或跨会话提权凭据。
- 消息与回复统一使用 `steer`：在当前模型请求和工具执行／工具批次结束后的下一个可接收步骤处理，不必等整轮最终回复，不抢占当前工具。若恰逢本轮结束或取消收尾，遵循 DSH 的下一轮回退语义。用户停止/归档和现有工具权限仍有效。
- Agent 使用稳定 request_id 去重；重试同 key 必须保持语义参数不变。结果未知时查正式 Session 日志对账，不盲目重复投递或创建。
- accepted 仅表示 Session flush 已确认接受；admitted 表示已进入模型步骤；均不等于完成。任务结果通过显式回复体现。
- 回执里的 `sessionMessageId` 是 Session 事件 id；`collab_reply.message_id` 必须使用协作记录 id（envelope 的 `Collaboration id` 或 `collab_inbox` 的 `id`）。
- 插件域保存投递意图/模型排序，模型实际收到的内容在 Session 正式日志中；回执用纯增量投影派生。不写自定义 Session 事件类型。
- 停用插件会清理注册和插件持有的新会话运行句柄，持久化的 Session/消息不删除。其他已有会话不被插件终止。
- 为防止无限互相确认，有每会话频率和创建数量保护；不自动转发普通模型输出。
- 模型排序保存采用 revision 比较；失败保留本地草稿，不能静默覆盖另一个窗口的排序。

## 开发与测试

运行 `node --test test/*.test.js`，并用 `node --check` 检查各 JavaScript 模块。

注入开销：系统提示词 740 B；六个工具的描述合计 1,556 B、参数合计 3,558 B。难度/模型/强度的规则只在 `collab_models` 和 `collab_create_session` 的说明里各出现一次，参数描述不重复工具描述。

当前入口是 `index.js`，领域逻辑在 `core.js`。`contracts.js` 是存储/工具/投影契约，`index.js` 只注册 Host 能力与仅供排序、查看日志的认证 API，`client.js` 只提供模型排序与只读日志，不导入私有 UI 包。
