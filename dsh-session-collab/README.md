# 自主会话协作 / Autonomous Session Collaboration

让同一 Host/profile 下的独立会话自动协作：人只需把任务交给 Agent，无需维护通讯录、勾选工作区或手动发信。不修改 DSH Core。

## 使用逻辑

- 所有普通、未归档且已加载为 running/idle 的会话默认参与。`collab_discover` 返回真实会话名、工作区、状态与内部路由 ID；按名称查询时，只有没有同名的 live 会话匹配，才会检查已关闭的持久会话。
- Agent 自行判断要联系谁，调用 `collab_send`：空闲对方自动唤醒；忙碌对方通过 `steer` 在下一个安全的模型步骤接收消息（不抢占当前工具调用）。**已关闭的会话会自动重新打开再投递**：显式给 ID 时直接唤醒；按名称时若只有唯一匹配的已关闭会话，也会先唤醒。
- 会话名称允许重名（同工作区也可以）。发信支持 `target_name` 和可选 `target_workspace`：唯一目标直接发送；用户已明确给出工作区或既有上下文能唯一定位时自动发送；否则由 Host 调用 DSH 的用户提问机制让你选择，未选择前不投递、不群发。单独填一个内部 ID 不能绕过重名检查。
- 确实已有唯一任务上下文时，Agent 可用精确 ID + `target_context` 引用该依据；这只是模型提供的上下文说明，不是用户授权凭据，不能杜撰来逃避询问。回复沿原消息线程；重试同一个 `request_id` 不重新解析名称或转投另一个会话。
- 收到问题的 Agent 自己用 `collab_reply` 返回结果或追问。
- 需要新协作者时调用 `collab_create_session`：提供工作区（可省略，用当前工作区）、描述性名称、初始任务，以及二选一的模型来源——任务难度 1–5，或用 `model` 直接指定可用区里的一个模型；可选 `reasoning_effort` 指定该模型支持的一档（省略用最高档），可选 `agent_preset` 指定模式（省略用默认模式）。
- 新协作者与 DSH 原生新会话使用同一用户默认权限；不强制只读、不继承发送方临时提权，也不改变全局默认模型。
- 插件**不是**后台自动转发所有聊天内容：只有主动发送的协作内容会进入另一会话，不共享完整私人历史。

## 工具一览

| 工具 | 作用 |
| --- | --- |
| `collab_discover` | 列出可协作的会话（名称、工作区、状态、重名标记） |
| `collab_send` | 向另一个会话发送协作消息 |
| `collab_reply` | 沿原线程回复收到的协作消息 |
| `collab_inbox` | 读取自己收到的协作消息 |
| `collab_models` | 查询可用模型、各自支持的思考强度与可用 Agent 模式 |
| `collab_create_session` | 创建新协作者会话并下达初始任务 |

## 唯一设置：模型排序

侧栏「更多」菜单里的「自主协作」打开模型排序页：

1. 上方可用区从上到下表示简单任务到专家级任务使用的模型顺序；拖动排序，拖到下方停用区即不再使用，拖回重新启用（不用复选框）。拖动后自动保存，也提供上移/下移/停用/启用按钮支持键盘操作。
2. Agent 评估 difficulty：1 简单、2 有限任务、3 常规实现、4 复杂跨模块、5 专家架构/不确定研究。模型索引为 `round((difficulty−1) × (可用模型数−1) / 4)`。也可以不按难度，直接用 `model` 指定可用区里的模型；停用区和不在名单里的模型一律拒绝。显示名、模型 id、`provider/model` 都可用来匹配。
3. 默认采用被选模型支持的最高思考强度；创建时可显式传 `reasoning_effort`，不支持的档位直接拒绝，不静默降级。没有思考强度的模型不接受该参数。
4. 模型来源仅是当前 DSH 已注册提供方公开的模型目录：已不存在的提供方、成功刷新后已移除的模型自动从排序中清除，不从历史设置复活；新增模型进入停用区，仍存在的模型保留相对顺序；目录临时查询失败不误判为永久移除。
5. 全部模型停用时，新建协作者明确失败，不偷偷继承其他模型。Agent 可查询和选用可用区模型，但不能重排、启用模型或指定停用模型。
6. 排序保存采用 revision 比较；失败保留本地草稿，不会静默覆盖另一个窗口的排序。

## 状态与边界

- 仅限同一 Host/profile；只发现当前 live 的普通会话，历史未加载或已归档会话不自动唤醒。Subagent 保持原生父子路由，其作用域隐去这六个协作工具（调用路径仍以 `NOT_INDEPENDENT` 拒绝）；已持久化但关闭的 subagent 会话也不进入候选。
- Peer 消息保留 DSH `agent-message/relay` 来源，并在模型输入中标注会话名；**不能**作为人类批准、系统指令或跨会话提权凭据。
- 消息与回复统一走 `steer`：在当前模型请求和工具批次结束后的下一个可接收步骤处理；若恰逢本轮结束或取消收尾，遵循 DSH 的下一轮回退语义。用户停止/归档和现有工具权限仍有效。
- 回执中的 `accepted` 仅表示会话已确认接收，`admitted` 表示已进入模型步骤，**均不等于任务完成**；任务结果通过显式回复体现。回执里的 `sessionMessageId` 是会话事件 id；`collab_reply.message_id` 必须使用协作记录 id（消息信封的 `Collaboration id` 或 `collab_inbox` 的 `id`）。
- Agent 用稳定 `request_id` 去重；重试同 key 必须保持语义参数不变。结果未知时查正式会话日志对账，不盲目重复投递或创建。
- 插件域仅内部保存投递意图（去重、回复路由、限流）和模型排序，不提供通信日志页面；模型实际收到的内容在会话正式日志中。不写自定义会话事件类型。
- 有每会话频率和创建数量保护，防止无限互相确认；不自动转发普通模型输出。
- 停用插件会清理注册和插件持有的新会话运行句柄；持久化的会话/消息不删除，其他已有会话不被终止。

npm test    # node --test test/*.test.js

入口是 `index.js`（注册 Host 能力与仅供模型排序的认证 API），领域逻辑在 `core.js`，`contracts.js` 是存储/工具/投影契约，`client.js` 只提供模型排序页，不导入私有 UI 包。
